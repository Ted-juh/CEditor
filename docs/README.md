# CEditor docs index

## Scripting — read in this order

| # | Document | What it is |
|---|---|---|
| 1 | [Getting started](scripting-getting-started.md) | Your first script: the Behavior Designer, the picker, live preview, Test / Trace. |
| 2 | [Scripting manual](scripting-manual.md) | **The user-facing API reference.** Generated from `panelApi.js` (`npm run docs:manual` in `CE/web`) — never edit it by hand; a test fails when it's stale. |
| 3 | [API explorer](api-explorer.html) | The same API as a browsable page: search, one worked example per command, the option tables, screenshots of every component. Generated by `node tools/scripts/gen-api-explorer.mjs`; open the file in a browser. |
| 4 | [Scripting cookbook](scripting-cookbook.md) | Task-based recipes: link controls, fill the panel from a dump, blink an LED on a timer… |
| 5 | [Panel API spec](design/panel-api-spec.md) | The design decisions (Q1–Q11) behind the API — the contract and its *why*. |
| 6 | [Scripting redesign plan](design/scripting-redesign-plan.md) | Why scripting works this way: lifecycle spine, scope layers, the many-real-languages model, Model 2 runtime. |
| 7 | [Language options & shippable export](scripting-language-options-and-shippable-export.md) | Per-language toolchains, installer options, exporting from an installed app. |
| — | [Scripting architecture plan](design/scripting-architecture-plan.md) | ⚠️ **Historical.** The retired command-graph model; superseded by 5 and 6. |

Working notes on what the API advertises versus what the C++ runtime backs, and on the timer
system, lived in `CE/web/src/CE_Application/docs/` and were deleted with the rest of that tree.

Editor and tooling design records have their own index at [docs/design](design/README.md).
The component and panel-part design notes that used to sit in `CE/web/src/CE_Application/docs/` were
deleted deliberately — the code and its tests are the record now. Git history has them if the
reasoning behind a component is ever wanted again.
