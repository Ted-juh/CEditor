The API tab

Built on 2026-09-10. These are drawings; the shipped tab matches them closely. Every number and every disagreement below was measured first — both editors mounted in Chromium for the heights, and the shipped package validator run side by side with the shipped path resolver for the rest.
Plate 1

The height does not depend on the contract

This is not the usual "the panel is too tall" case. It is the opposite. The sections that define what a component publishes show one entry at a time behind a dropdown, so they render at the same height whether the contract has eight entries or fifty. The section that lists the contract is read-only and sits right underneath.

Plate 2

Three answers to one question

An editable property whose path is Parts.background.Background.Fill.nonsenseKey, on a component that really does have a background part:

  • The package validator checks the FIRST segment of a path and passes everything after it, so it reports nothing.
  • The author's editor tests only whether the path is an empty string, so it reports nothing.
  • The instance panel resolves the whole path, gets undefined, and drops the row — with no message anywhere.

The author is the only person who can fix it and the only one not told. The tab gives the author the instance panel's answer, because that is the one that decides whether the entry exists at all.

Plate 2

The third finding, in one panel: the application's own factory publishes accentColour against a variable rather than a channel, and nothing in the application reads variable. Every custom component made from that factory ships with an input the instance panel refuses to show. Applying the repair writes the channel and clears the stale field beside it — leaving it would be the next reader trusting it.

Decided while building

  • The tab reports the shipped default, it does not change it. Changing createCustomComponentPublishedPropertiesDefaults changes what every new component gets, which is the owner's call rather than a side effect of a dock tab.
  • A withheld entry is not a broken one. The first draft flagged any unresolvable target; saying a switched-off entry "never reaches a consumer" is true and useless.
  • Adding and removing entries stays in the panel. This tab edits the contract that exists — one job, done properly.
