The Effects tab

1,902px of properties over four owners, and eleven text effects whose stacking order is currently eleven numbers you cannot see the result of.

Nothing here is built. Drawings, not screenshots. The field names, defaults and order numbers are real — read out of sectionDefaults.js and CanvasControl.svelte.
No sliders. Nothing in this tab is a horizontal, vertical or radial slider. Numbers use NumberCell, which already ships: the label is a drag handle, the steppers give exact increments, and the value is always typeable. Three ways in, no track.

Plate 3

Two things that are specific to this app

Per-effect thumbnails

With nine effects live, nothing tells you which one is producing what you are looking at. Each stack row carries a thumbnail of that layer alone — the way a mixer shows a meter per channel. It is cheap here because the renderer already draws each effect as its own layer.

The state strip

Effects in this app are state-scoped: a shadow can exist on base and vanish on pressed. Today the only way to find that out is to hover the real control. Four small specimens make it visible while editing, and a badge marks a state where the effect is switched off. A general graphics tool has no states to show — this is worth building because CEditor does.

Plate 3

Deliberately absent: dragging the shadow around on the specimen. That is Photoshop's gesture and it is the same fiddliness already rejected for arc handles — the offset is two numbers, and two NumberCells beat chasing a blurred copy with the pointer.

Plate 4

What stays in the properties panel

The open question from the space plan, answered for this candidate. The panel keeps one row — the effect toggles that already exist there, one span={4} cell — plus a button that opens the tab. With the dock hidden you can still switch an effect on and off; you cannot tune it. 77px instead of 1,067px, and the group is relocated rather than lost.

Open

  • Does the tab follow the selection? Colour clears its target when the selection changes. Effects probably wants to retarget instead — which makes it a second properties panel in one respect, and that should be a decision rather than a default.
  • Component effects and Lighting in the same tab? Component Effects is a different shape — Shadows.items[] is an array, and Filters (brightness, contrast, saturation, hue, grayscale, sepia, invert) is a colour grade rather than a stack. Probably a second mode in this tab, but it may be cleaner to ship text effects first.
  • Leave the order-60 tie alone? Existing documents carry it, and priority resolves it consistently. Making the stack draggable lets an author separate them; forcing it would change how saved panels render.
