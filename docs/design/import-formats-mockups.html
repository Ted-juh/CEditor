Four more ways in: Illustrator, Figma, 3D parts and glTF

The four routes the design record lists as next (docs/design/changeable-control-sets.md, "Native files" and "Order"), drawn as they would look in CEditor, with the questions that need your answer before they are built. Everything that has no screen of its own (the PDF reader, the glTF reader, the layer splitting) can be built while you look at this.

1 · Illustrator and PDF

An .ai file opens wherever an SVG does

An Illustrator file saved with Create PDF Compatible File (Illustrator's default) carries a PDF copy of the artwork. CEditor reads that copy with pdf.js (Mozilla, Apache 2.0), turns it into an SVG in memory, and hands it to the SVG import that exists, so panels, Update Panel and components all work the same way. Any PDF opens the same way, from Affinity, Inkscape or anywhere else.

What the import says

ImportedA dial of 6 layers, read from the PDF part of Knob vintage.ai. Named from its top-level layers: pointer, cap, skirt, shadow, lamp on, lamp off. The pointer turns about the knob's middle.
ImportedA panel with 14 controls from Synth front.pdf, page 1 of 1. The placeholders came from the layer named components and were typed by their colour and shape (red circles: knobs; long red rectangles: sliders), since a PDF keeps no names for them: knob 1 to knob 9, slider 1 to slider 4, button 1. Rename them in the Layers list.
Not importedKnob old.ai was saved without PDF compatibility, so its artwork is only in Illustrator's own format, which CEditor cannot read. In Illustrator, choose File › Save As, tick Create PDF Compatible File, and open it again; or use File › Export As › SVG.
Notices

The same notice the SVG and Photoshop imports give, with where the names came from. A PDF keeps the top-level layers' names and nothing below them, so the two conventions that need names say how they were met.

What comes in

In the fileIn CEditor
Top-level layersLayer groups, by their names: components for a panel's placeholders, pointer, cap, lamp on for a component's parts. Hidden layers stay hidden.
Paths, fills, strokesVector layers, as the SVG import makes them. Dashes, joins, caps and even-odd fills kept.
GradientsLinear and radial gradients. A freeform or mesh gradient, which a PDF stores as a mesh, becomes a picture.
Clipping masksThe layer's mask, as for SVG.
Opacity and blend modesKept, as in the Photoshop import.
Placed and embedded imagesPicture layers.
TextText where the PDF says the font, its size and colour; otherwise its outlines, so it looks right but is no longer editable as text.
CMYK colourConverted as Acrobat shows it without colour management (pdf.js's own conversion).
Sublayers and object namesNot read. Illustrator keeps them only in its private data, which is undocumented. Name a moving part as a top-level layer, or export SVG.
ArtboardsA PDF page each. A file with several asks which one.
2 · Figma

A plugin that exports a frame for CEditor

Figma's own file format is undocumented and changes without notice, so CEditor does not read it. Figma's supported way is a plugin: a small program that runs inside Figma. This one, CEditor Export, does what the Blender add-on does: it lists what each layer of the selected frame will do in CEditor, warns about what will not come across, and saves an SVG with every layer's name kept, which New Component from Vector Artwork or New Panel from Vector Artwork opens as it is. Nothing changes in CEditor itself.

In Figma

The plugin's window beside the canvas. It reads CEditor's own words for what moves (the same list the add-on and the importers share), so a Figma layer named pointer turns as a Photoshop one does. Variants of a component set become the states CEditor already reads from names. Installed once from tools/figma-plugin/manifest.json (Figma › Plugins › Development › Import plugin from manifest); it needs no account, token or network.

A live link instead (Update from Figma, pulling a frame by its link through Figma's web API) is possible later. It needs your Figma access token and the network, and gains only that you skip saving the file.

3 · CEditor's own 3D parts

A knob built from settings, rendered, and changeable down to its shape

A 3D part in the Component Designer is a small scene: a body, a top, a pointer, a lamp, each an object with a shape, a material and a motion. CEditor renders it from straight above, lit by the set's lamp, and turns it into the same layers the Blender add-on writes: each object's colour, its shading and highlights, the light on it and its gloss, its shadow, its frames for the angles it turns through. From there everything that works for a Blender knob works for it, the recolouring of this week included, and an exported plug-in draws it with nothing new.

Designer

A new 3D tool in the tool strip places a 3D part, starting as a knob (skirt, body, top, pointer). Its objects are listed under it in the Layers list with what they do; a new 3D tab in the dock edits the selected object. The shapes are piece E's vocabulary (turned bodies, knurled or fluted, tops, blocks), now with a pointer of its own (line, bar, chicken-head, dot) and lamps. The light is the set's lamp. Add Object and Remove sit at the bottom of the tab.

What happens when you change something

ColourInstant

The colour is a colour layer with its light written beside it, worked out again in the new colour as for a Blender knob. No render.

ValueInstant

The turning objects are frames that follow the value, as an imported dial's pointer does. No render.

Shape, finish, lampA render

Estimated at half a second to two seconds on a graphics card, the old layers shown meanwhile; on Linux, whose webview has no graphics card, several seconds. Measured once it is built.

ExportNothing new

The layers are kept with the component, so the plug-in draws pictures, as it draws an imported knob.

4 · glTF

A model from Blender, each object a part you can change

glTF is the exchange format Blender, and most 3D programs, export (File › Export › glTF 2.0; a .glb, or a .gltf with its .bin and textures). CEditor reads its meshes and materials and makes the same 3D part as section 3, with the file's objects in place of the built ones: the names say what moves, by the same words as everywhere else, and each object's material (colour, metal, roughness) can be changed. The shapes stay the file's: CEditor does not edit meshes.

How close to Blender

CEditor's renderer draws as Blender's real-time engine (Eevee) does, not as Cycles: soft shadows and reflections of a studio room, but no light bouncing between parts, so the skirt under a brass cap is not warmed by it. For a knob that has to look exactly like Blender's own render, the add-on route stays: it writes Cycles' light into the file.

Decisions

What needs your answer

D1How do .ai and PDF files go into the File menu?
A · Rename the SVG items"New Panel from Vector Artwork...", "Update Panel from Vector Artwork...", "New Component from Vector Artwork...", each opening SVG, PDF and .ai.
B · Items of their ownThree more items beside the SVG ones; the menu grows from six artwork items to nine.
D2Where do an Illustrator file's names come from?
Top-level layers onlyWhat the PDF part keeps. A moving part is named as a top-level layer; for named placeholders on a panel, SVG export as today.
Also Illustrator's private dataSublayer and object names, read from an undocumented, compressed format that Adobe changes between versions. Larger, and fragile.
D3How does Figma come in?
A plugin that saves an SVGRuns in Figma, checks the names, saves an SVG with them; CEditor unchanged. No token, no network.
A plugin that writes a component fileSkips the SVG step, but duplicates the SVG import inside the plugin and has to follow every change to CEditor's file format.
A live link through Figma's web APIUpdate from Figma by link. Needs your access token and the network. Possible later on top of the plugin.
D4What renders 3D parts and glTF models?
three.js, in the editor onlyMIT, the standard web 3D library: reads glTF, draws physically based materials and soft shadows, and builds turned bodies from a profile. About 700 KB, loaded only when a 3D part is open; never in the plug-in.
Extend piece E's shaderAlready draws turned bodies, but it describes shapes as formulas and cannot draw a mesh, so glTF would need a second renderer anyway.
D5How is a 3D part kept and drawn?
Rendered into layers, as the add-on writes themColour changes and the value are instant; the plug-in, the Player and the filmstrip baker draw it with what they have. A shape change is a render.
Drawn live, baked to a filmstrip at exportEvery change in the editor is a render, colour included; the plug-in carries a picture for every step of the value, many times larger.
D6Do the sets' rendered knobs (piece E) move to the new renderer?
Not nowThey keep their shader and their look; every set stays as it is. A set can use a 3D part later, as it can name a library component today.
Yes, one rendererOne look everywhere, but every rendered set knob changes how it looks, and the export bake for them is redone.
D7In what order?
1, 2, then 3 with 4 on topIllustrator and PDF; the Figma plugin; the 3D part with built shapes; glTF objects in the same part. Each one finished, documented and pushed before the next.
As listed, 4 before 3glTF first, built shapes after. glTF alone needs the whole 3D part all the same, so it saves nothing.

What would help from you

  • An Illustrator file with top-level layers (a knob, or a panel with a components layer), if you have Illustrator: the test files here will be PDFs written to Illustrator's layout, and a real one is the check that matters.
  • A glTF of a knob from your Blender scene, if you have one: the test model here is the add-on's test knob, exported.
  • Figma: nothing. The plugin is tested here against a stand-in for Figma's API; you would be the first to run it in Figma.
